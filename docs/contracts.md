# Contracts Subsystem (`rust_core/contracts`)

The `contracts` crate acts as the central nervous system and single source of truth for data structures across the entire `llm-pdf-ingest` monorepo. It contains no active data processing or business logic. Instead, it strictly defines the schemas, types, and error enumerations that allow the native Rust backends (`parser`, `agent_harness`, `inference`, `dbs`) to communicate safely with each other and with the React Native TypeScript frontend.

---

## 1. Unified Semantic Schema (The `ASTNode`)

At the core of the application is the Semantic Abstract Syntax Tree (AST). The `contracts` module defines the explicit Rust structs (e.g., `StructuredBlock`, `StructuredSection`, `ASTNode`, `BlockType`) that represent the layout and semantic meaning of a document.

* **Database Parity:** The `ASTNode` and associated structural definitions here are not just temporary transit payloads. They strictly mirror the schema persisted within the SQLite `blocks` and `sections` tables managed by the `dbs` module.
* **Extensibility:** The AST is designed to be multi-format compatible. Whether a document originated as a raw double-column PDF (processed by the `agent_harness`) or an EPUB natively parsed bypassing the LLM, the resulting data is universally formatted into these exact `contracts` structures.

---

## 2. Auto-Generated TypeScript Bindings (`ts-rs`)

To eliminate cross-runtime serialization bugs and maintain strict type safety across the C++ JSI bridge, the frontend does not manually define its own interfaces.

* **Single Source of Truth:** Rust structs in the `contracts` crate are decorated with `ts-rs` macros (e.g., `#[derive(TS)]`).
* **Build-Time Generation:** During the build process, the Rust compiler automatically generates accurate TypeScript definitions (e.g., `ASTNode.ts`, `StructuredBlock.ts`) and outputs them into the `rust_core/contracts/bindings/` directory.
* **Frontend Consumption:** The React Native app (`mobile/src/shared/types/`) imports these auto-generated bindings directly, ensuring the UI always expects the exact JSON shape that the Rust core will deliver.

---

## 3. Centralized Error Handling (`error.rs`)

To uphold the strict "No Panics" engineering guardrail across the native pipeline, the `contracts` crate houses the unified error propagation architecture.

* **The `AppError` Enum:** Using the `thiserror` crate, `error.rs` defines a comprehensive, strongly-typed `AppError` enumeration.
* **Module-Specific Variants:** It encapsulates discrete failure states from across the pipeline, such as `ParserError` (corrupted PDF streams), `InferenceError` (LLM context overflow or malformed ReAct JSON), and `DatabaseError` (SQLite constraint violations).
* **Safe UI Bubbling:** Because all Rust modules (`parser`, `agent_harness`, `dbs`) return `Result<T, AppError>`, any failure deep in the native pipeline is safely caught, formatted, and bubbled up across the JSI bridge as a clean exception that the React Native UI can catch and display gracefully.

---

## 4. Pipeline Transfer Payloads

Beyond the final AST, the `contracts` module also defines the intermediate payloads passed between the ingestion stages:

* **`PageExtraction` & `ExtractionChunk`:** The raw layout coordinates and 100-token overlap buffers generated by Pass 1 (`parser`) and handed to Pass 2 (`agent_harness`).
* **`ExtractedImageMetadata`:** The cryptographic SHA-256 hashes, byte sizes, and sandbox `local-asset://` URIs for extracted graphics.
* **`LLMStructuringOutput`:** The strict JSON schemas (enforced via `serde`) that the Hugging Face models are constrained to output when building indices or formatting text.
